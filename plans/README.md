## Findings considered and rejected (so they aren't re-audited)

- **`proxy.ts` only checks for a session cookie, not the role** — by design.
  Full authorization is enforced server-side in each protected layout
  (`fetchAuthQuery(api.profiles.getRole)` in `staff`/`super-admin`/`dashboard`/
  `account` layouts) **and** re-checked inside every privileged Convex query
  (`requireOperator` / `requireSuperAdmin`). Genuine defense-in-depth; not a hole.
- **`promoteSelfToSuperAdmin` self-elevation** — a guarded bootstrap path: it
  refuses once any `super_admin` exists and (for non-staff) once any operator
  exists. Fails closed. Intentional first-admin bootstrap, not a vulnerability.
- **`DevRoleSwitcher` (`src/components/dev/role-switcher.tsx`)** — renders only
  navigation `<Link>`s and is gated by `NODE_ENV !== "production"`; it changes
  no roles. Not a finding.
- **`mirrorBetterAuthRole`'s `ctx: any`** — a documented escape hatch for lagging
  Better Auth component codegen types (TODO comment present). Low value to chase.
- **`apps/design-lab`** — zero git-tracked files (only gitignored
  `node_modules`/`.next`/`tsbuildinfo`). Untracked local scaffold, not in the
  repo; nothing to fix.
- **Dependency version lag** — none worth acting on: Next 16.2.6, React 19.2,
  Convex 1.34, Better Auth 1.6 are all current. (A runtime `bun audit` was not
  run; deps are modern.)
